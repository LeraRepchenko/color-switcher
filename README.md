# Лабораторная работа №3. QTimer, лямбда-слоты и динамические соединения

## Цель работы

Освоить класс QTimer для периодического и однократного выполнения кода, научиться использовать лямбда-функции в качестве слотов, а также создавать, разрывать и переподключать соединения между сигналами и слотами динамически, во время выполнения программы.

## Постановка задачи

Реализовать приложение ColorSwitcher:

1. Окно с холстом, цвет которого меняется по таймеру в трёх режимах: цикл, случайный цвет, мигание.
2. Панель кнопок для управления таймером и интервалом.
3. Динамическое создание кнопок-цветов.
4. Очистка палитры с явным разрывом соединений через QMetaObject::Connection.
5. Обработка кликов мыши по холсту через mousePressEvent с излучением сигнала colorChanged.
6. Переключение обработчика сигнала colorChanged «на лету».

## Теоретическое обоснование

**QTimer** — объект, который по истечении заданного интервала излучает сигнал timeout(). Интервал задаётся в миллисекундах. Методы: start() запускает повторяющийся таймер, start(ms) — одноразовый, stop() останавливает, isActive() проверяет состояние. Статический метод singleShot(ms, receiver, functor) вызывает функцию один раз без создания объекта.

**Таймер и цикл событий.** В отличие от консольного калькулятора ЛР1, где stdin читался в блокирующем цикле, таймер не может работать без цикла событий Qt. QTimer регистрируется в event loop и срабатывает, когда управление возвращается в app.exec(). Поэтому в GUI-приложении вызов app.exec() обязателен — без него окно отрисуется один раз и «замрёт».

**Лямбда-слоты.** Начиная с Qt5, connect() принимает лямбды. Захват переменных: [=] копирует значения, [&] ссылается (опасно, если переменные живут меньше лямбды), [this] захватывает указатель на объект класса, [ptr] — конкретный указатель. Опасный антипаттерн — захват по ссылке локальной переменной, которая умрёт по выходе из скоупа.

**Контекст подключения** (третий аргумент connect) — объект, привязывающий жизнь соединения. Когда context уничтожается, Qt автоматически разрывает соединение. Если context — часть дерева объектов ЛР2, при удалении родителя соединение тоже разорвётся.

**Динамические соединения.** Результат connect() — объект QMetaObject::Connection, хранящий идентификатор для последующего разрыва через disconnect(conn). Qt::UniqueConnection запрещает дубликаты соединений. При удалении отправителя или получателя Qt автоматически рвёт соединения.

**События vs сигналы.** События — виртуальные методы виджета: mousePressEvent(), keyPressEvent(), paintEvent(). Переопределяются в подклассе. К ним нельзя подключиться через connect(). Сигналы — высокоуровневые уведомления: clicked(), собственный colorChanged(). В работе они комбинируются: холст переопределяет mousePressEvent, внутри излучает сигнал colorChanged.

**Ошибки компиляции и линковки.** Сообщение `'X' was not declared in this scope` выдаёт компилятор — метод не объявлен в теле класса. Сообщение `multiple definition of 'X'` выдаёт линкер — определение попало в два .o. Сообщение `undefined reference to 'X'` — тоже линкер: объявление есть, определения нет. Undefined reference появляется только после успешной компиляции всех .o.

## Разбор ошибок и их решений

**Ошибка 1. multiple definition of 'MainWindow::...'**
Компиляция зелёная, линковка падает с multiple definition по всем методам MainWindow. Причина — mainwindow.cpp попал в сборку дважды (в .pro был указан дважды). Решение: удалить дубли из .pro, оставить mainwindow.cpp только один раз в SOURCES, удалить папку build и пересобрать.

**Ошибка 2. Лямбда без контекста подключения.**
Плохо: connect(&m_timer, &QTimer::timeout, [this]{...}). Хорошо: connect(&m_timer, &QTimer::timeout, this, [this]{...}). Без контекста после удаления окна таймер дёрнет мёртвый код.

**Ошибка 3. Захват по ссылке на локальную переменную.**
Локальная переменная умрёт по выходе из скоупа, а лямбда останется. Решение: захват по значению или поле класса + [this].

**Ошибка 4. Таймер «молчит».**
Причина — отсутствие app.exec() или запуск не в том потоке. В GUI без цикла событий timeout() не придёт никогда.

**Ошибка 5. Дублирование соединения.**
Дважды вызванный одинаковый connect приводит к двойному срабатыванию слота. Решение: хранить QMetaObject::Connection и делать disconnect перед connect, либо использовать Qt::UniqueConnection.

**Ошибка 6. Обращение к удалённой динамической кнопке.**
После deleteLater() сырой указатель становится висячим. Решение: QPointer<PaletteButton> + проверка isNull() (связка с ЛР2).

## Вывод

В ходе работы изучены три технологии Qt. QTimer — периодический вызов кода через сигнал timeout(), работает только при запущенном цикле событий. Лямбда-слоты — connect() с лямбдой и контекстом подключения, который обязателен при использовании this. Динамические соединения — QMetaObject::Connection позволяет хранить идентификатор и разрывать соединение через disconnect(), что даёт возможность переподключать сигналы на разные обработчики без пересоздания объектов.

Также освоены различия между событиями и сигналами: mousePressEvent переопределяется, а внутри излучает собственный сигнал colorChanged. Различие ошибок компиляции и линковки: multiple definition и undefined reference — ошибки линкера, not declared in this scope — компилятора.

Применение в сквозном проекте: QTimer пойдёт на автосохранение, динамические соединения — на обработчики кнопок в списке игр, кастомный виджет с paintEvent — на графики статистики.

## Контрольные вопросы

**1. Что такое QTimer и какой сигнал он излучает по истечении интервала?**
Класс Qt для периодического или однократного выполнения кода. Излучает сигнал timeout() по истечении заданного интервала в миллисекундах.

**2. Чем start() отличается от start(ms) и от QTimer::singleShot()?**
start() — повторяющийся таймер с текущим interval(). start(ms) — одноразовый с указанным интервалом. singleShot(ms, receiver, functor) — статический метод, вызывает функцию один раз без создания объекта QTimer.

**3. Почему QTimer не работает без app.exec()? Что такое цикл событий?**
QTimer регистрируется в цикле событий Qt. Без app.exec() программа завершается до срабатывания таймера. Цикл событий — бесконечный цикл, обрабатывающий клики, перерисовку, таймеры, сетевые сокеты.

**4. Чем GUI-приложение с таймером принципиально отличается от консольного калькулятора ЛР1?**
В ЛР1 был блокирующий ввод stdin — цикл событий не нужен. В GUI — событийная модель: программа реагирует на события. Без app.exec() цикл событий не запустится.

**5. Что произойдёт, если лямбда-слот захватывает this, но контекст подключения не передан?**
При удалении объекта соединение не разорвётся. Лямбда продолжит обращаться к удалённым полям this — неопределённое поведение или падение.

**6. Зачем третий аргумент connect() (context object) и как он связан с деревом объектов ЛР2?**
Context привязывает жизнь соединения к объекту. При удалении context Qt автоматически разрывает соединение. В дереве объектов Qt при удалении родителя удаляются дети, и если context — ребёнок, соединение рвётся автоматически.

**7. Чем захват [=] отличается от [&]? Когда [&] опасен?**
[=] копирует значения. [&] ссылается на переменные. [&] опасен, когда лямбда переживает свою область видимости — ссылка становится висячей.

**8. Что такое QMetaObject::Connection и как разорвать соединение по нему?**
Объект, возвращаемый connect(). Хранит идентификатор конкретного соединения. Разрывается через disconnect(conn).

**9. Что такое Qt::UniqueConnection и какую проблему решает?**
Флаг, запрещающий дубликаты соединений. Защищает от двойного срабатывания при случайном двойном connect.

**10. Что будет, если вызвать одинаковый connect() дважды на одних объектах?**
Слот сработает дважды при каждом сигнале. Симптом: цвет «прыгает» на 2 позиции за тик. Решение: disconnect перед connect или Qt::UniqueConnection.

**11. Рвёт ли Qt соединения автоматически при удалении отправителя, получателя или контекста?**
Да. При удалении любого из объектов, участвующих в соединении, Qt автоматически разрывает его.

**12. Почему для удаления динамической кнопки лучше deleteLater(), чем delete?**
deleteLater() безопаснее, потому что удаляет объект через цикл событий, когда управление вернётся в app.exec(). delete удаляет немедленно — опасно внутри слотов, так как объект ещё участвует в стеке вызовов.

**13. Чем mousePressEvent() отличается от сигнала clicked()? Можно ли подключиться к событию через connect()?**
mousePressEvent — виртуальный метод, переопределяется в подклассе. clicked — сигнал. К событиям нельзя подключиться через connect(), к сигналам — можно.

**14. Что такое eventFilter() и когда он удобнее переопределения виртуального метода?**
Механизм перехвата событий чужих объектов. Удобен, когда нужно фильтровать события другого объекта без создания подкласса.

**15. Как реализовать мигание одним таймером без второго таймера?**
Хранить флаг m_blinkOn. На каждом timeout инвертировать флаг и менять цвет холста.

**16. Что произойдёт, если менять interval() у активного таймера?**
Новый интервал применится со следующего тика. Текущий отсчёт не сбросится.

**17. Почему состояние режима хранится в поле m_mode, а не захватывается в лямбду?**
Потому что при переподключении лямбды старое захваченное значение потерялось бы. Поле читается при каждом срабатывании — режим всегда актуален.

**18. Как проверить срабатывание timeout в юнит-тесте без реального ожидания?**
Использовать QSignalSpy и вызвать QTest::qWait() с малым интервалом, либо вызвать слот напрямую.

**19. Можно ли использовать QTimer в потоке без цикла событий? Что для этого нужно?**
Нельзя. QTimer требует цикла событий в том потоке, где создан. В отдельном потоке нужно запустить QEventLoop или QThread::exec().

**20. Как динамические соединения связаны с автоудалением детей из ЛР2 при очистке палитры?**
При очистке палитры мы явно рвём соединения через disconnect, а потом удаляем кнопки через deleteLater. Это безопаснее, чем полагаться на автоудаление.

**21. Чем сообщение компилятора not declared in this scope отличается от сообщения линкера undefined reference?**
Not declared — ошибка компилятора: метод не объявлен в теле класса. Undefined reference — ошибка линкера: объявление есть, определения нет. Первое — добавить объявление в .h, второе — убедиться, что .cpp в SOURCES.

**22. Почему multiple definition возникает, когда тело метода есть и в .h, и в .cpp?**
Потому что определение попадает в два объектных файла: один из .h (при включении), второй из .cpp. Линкер видит два одинаковых символа. Решение: тело только в .cpp.

**23. Если компиляция прошла без ошибок, но линковка падает на undefined reference по всем слотам класса — где искать причину?**
В файле реализации. Либо .cpp не входит в SOURCES, либо содержит объявления вместо определений (например, случайно скопировали заголовок).
